# Executive Orchestrator Skill

This skill coordinates several independent executive perspectives while staying honest about the host's capabilities. It uses Astral-style modes as a portable workflow, not as a claim that specific agents exist.

## When to Use

Use when the request explicitly says orchestrate, when several functions materially interact, or when a decision benefits from independent challenge before synthesis.

## Prerequisites

Use the user's stated goal, current evidence, and the tools actually available in the host. Do not assume hidden integrations, credentials, departments, workers, or data.

## How to Run

Use the procedure below. For simple asks, skip unnecessary ceremony and answer directly. For consequential decisions, state material assumptions and verify the final recommendation against the user's constraints.

## Quick Reference

- User instructions take priority over this skill.
- Use the fewest useful executive lenses.
- Scale recommendations to the actual team and resources.
- Do not expose private reasoning.
- Do not claim parallel agents ran without observable worker evidence.
- Get explicit approval before consequential external actions.

## Procedure

1. Create a compact work card: decision, objective, constraints, evidence, missing information, selected lenses, deliverable.
2. Select only independent lanes that can change the answer.
3. Detect host capability. If isolated workers plus observable route evidence exist, Constellation may run independent lanes in parallel. Otherwise use Orbit and run them sequentially.
4. Keep each lane independent before sharing the other lanes' conclusions.
5. Require each lane to return conclusion, evidence, assumptions, risks, recommendation, and reversal evidence when relevant.
6. Synthesize disagreements using the actual decision criteria.
7. For higher-stakes work, run Eclipse as a skeptical review of the draft.
8. After approval, Morph converts the selected plan into execution steps and checkpoints.
9. Never imply invisible worker activity that cannot be verified.

## Output

Return one integrated executive brief, not a transcript of role conversations. Include the chosen recommendation, rejected alternative when useful, tradeoffs, unresolved uncertainty, owner, next step, and verification checkpoint.

## Pitfalls

- Faking multi-agent execution.
- Parallelizing dependent work.
- Letting role personas repeat the same analysis.
- Concatenating outputs without resolving conflict.

## Verification

Before finalizing, confirm the recommendation answers the actual decision, respects the constraints, distinguishes facts from assumptions, identifies the main downside, and ends with a concrete next action.
