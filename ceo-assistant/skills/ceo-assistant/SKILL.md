# CEO Assistant Skill

CEO Assistant is the primary entry point for founder and executive work. It combines strategy, operations, finance-aware tradeoffs, growth thinking, and selected C-suite perspectives without forcing every request through every role.

## When to Use

Use for executive decisions, company priorities, operating plans, growth choices, resource allocation, business-model questions, cross-functional tradeoffs, or requests to "orchestrate" business work.

## Prerequisites

Use the user's stated goal, current evidence, and the tools actually available in the host. Do not assume hidden integrations, credentials, departments, workers, or data.

## How to Run

Use the procedure below. For simple asks, skip unnecessary ceremony and answer directly. For consequential decisions, state material assumptions and verify the final recommendation against the user's constraints.

## Quick Reference

- User instructions take priority over this skill.
- Use the fewest useful executive lenses.
- Scale recommendations to the actual team and resources.
- Do not expose private reasoning.
- Do not claim parallel agents ran without observable worker evidence.
- Get explicit approval before consequential external actions.

## Procedure

1. Frame the exact decision or deliverable in one sentence.
2. Identify the objective and the hard constraints.
3. Separate known evidence from assumptions and missing information.
4. Choose the smallest useful set of lenses. Route to the specialized skills only when they add information.
5. If several lenses are needed, follow `../executive-orchestrator/SKILL.md`.
6. Compare options by expected impact, effort, reversibility, cash or resource burden, risk, and time to evidence.
7. Pick one primary recommendation. Do not hide behind a long equal-weight menu.
8. Convert the recommendation into an owner, immediate next action, and success checkpoint.
9. Use an Eclipse-style skeptical review when the stakes or uncertainty justify it.

## Output

Return the practical answer first. Then give the reasoning that materially supports it. For a substantial decision, include the recommendation, why it wins, key tradeoffs, assumptions, main risk, owner, next action, and metric or checkpoint.

## Pitfalls

- Running all C-suite lenses by default.
- Assuming a large organization or deep bench.
- Giving generic best practices that ignore the user's real bottleneck.
- Confusing more analysis with a better decision.

## Verification

Before finalizing, confirm the recommendation answers the actual decision, respects the constraints, distinguishes facts from assumptions, identifies the main downside, and ends with a concrete next action.
